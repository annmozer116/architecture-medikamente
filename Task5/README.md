# Task5. Cutover-план миграции. 

## Пояснительный текст к cutover-плану

**Этапы миграции.** Миграция разбита на подготовку (инфраструктура, абстракции, данные), тестирование, затем последовательный cutover по bounded contexts: сначала Согласия и Реестр пациентов как основа для остальных контекстов, затем Расписание (ключевой MVP — запись на приём), далее Биллинг с сохранением интеграции с 1С, затем Медицинские данные и интеграция с лабораторией, в конце — включение аналитики и полное отключение legacy. После каждого переключения выполняется мониторинг и при необходимости откат.

**Обоснование подхода.** Стратегия Branch by abstraction выбрана из-за отсутствия единого "старого" приложения и сложности надёжной синхронизации Excel/1С с новой системой (как при Parallel run). Введение абстракций по границам контекстов позволяет переносить функциональность по частям, не делая единовременного "большого взрыва", и сохранять возможность отката на уровне контекста.

**Управление рисками.** Критические риски (целостность данных, согласованность версий абстракций, надёжность legacy-адаптеров) закрываются инвентаризацией и валидацией данных, версионированием контрактов, тестами и репетицией отката. Для каждого этапа 3.x определены критерии отката и ответственные; общее решение об откате принимает руководство при участии технического директора.

**Распределение ответственности.** Технический директор отвечает за архитектуру, порядок cutover и откат; разработка и DevOps — за реализацию и эксплуатацию; QA — за тестирование и проверку политик; бизнес-аналитик — за данные и обратную связь с пользователями; руководство — за решение о переходе и откате на уровне бизнеса.
