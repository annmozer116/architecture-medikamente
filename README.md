# Архитектура и миграция — «Медикаменте»

Общая информация о проекте: текущее состояние (As-Is), цели миграции и целевое состояние (To-Be), принципы интеграций. Детали по заданиям — в папках Task1–Task6.

---

## Текущее состояние (As-Is)

- **Масштаб:** один офис, 20 административных и 15 медицинских сотрудников; планируется пятикратный рост объёма данных и открытие филиалов.
- **Данные и процессы:** журналы приёма, учёт пациентов и платежей, медкарты, анализы — в Excel и сканах на общем диске. Учёт денежных средств — «1С:Бухгалтерия предприятия» (файловый режим); ТМЦ — «1С:Торговля и склад». ККМ интегрированы с 1С по OLE.
- **Инфраструктура:** один физический сервер (Windows Server 2022) в здании офиса: Active Directory, DNS, DHCP, LDAP, файловый сервер, Exchange. Единого бэкенд-приложения нет; процессы в основном ручные, разрозненные данные.
- **Безопасность:** доменная аутентификация; разграничения доступа к данным и аудита на уровне приложений нет. PII/PHI в файлах без шифрования и тегирования; соответствие 152-ФЗ, 323-ФЗ, ФСТЭК не обеспечено.

## Цели миграции и целевое состояние (To-Be)

**Бизнес-цели:**
- Усилить безопасность медицинских данных и соответствие законодательству РФ.
- Поддержать пятикратный рост объёма данных и открытие филиалов.
- Перейти к единой системе хранения и управления данными с возможностью записи через портал и мобильное приложение (личный кабинет).

**Целевая система:**
- Единая платформа: порталы (клиенты, ресепшен, врачи), платёжный шлюз, CRM, интеграция с лабораторией по API.
- Доменная архитектура с bounded contexts: Реестр пациентов, Расписание, Согласия, Медицинские данные, Биллинг, Классификация данных, Аудит, Аналитика.
- MVP: запись на приём через портал, видимость записи для ресепшена, RBAC/ABAC по категориям данных.
- Целевое состояние: полная автоматизация записи, мобильное приложение, тегирование данных, аудит доступа, алертинг при несанкционированном доступе.
- НФТ: безопасность (конфиденциальность, своевременное удаление данных), масштабируемость (филиалы, рост команды, мобильные клиенты), сопровождаемость, конфигурируемость.
- Дополнительно: озеро данных для BI/ML/AI; целевое состояние должно обеспечивать соответствие 152-ФЗ и 323-ФЗ.

---

## Интеграции (целевое состояние)

**Лаборатория:** передача в лабораторию только минимально необходимых данных (ФИО, телефон, почта) по защищённому каналу (API с аутентификацией и TLS); приём результатов только в защищённый контур (API вместо незащищённой почты); сохранение результатов в зашифрованное хранилище с тегом PHI; контроль PII/PHI на API-шлюзе.

**1С:** бухгалтерия и ТМЦ остаются в 1С; биллинг новой платформы передаёт в 1С только нужные платёжные данные через ACL (Anti-Corruption Layer); защищённый канал (TLS/API) между кассой/приложением и 1С; внутренняя модель биллинга не зависит от формата 1С.
